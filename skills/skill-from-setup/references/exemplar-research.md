# Exemplar research

The goal is a short table of real pages that set the bar, and the reasons they set it.

## Find candidates

1. Search the place for companies in two or three categories close to the target company. Include both large and small companies.
2. Add pages that people in the field point to as good. Note who pointed to them.
3. Collect 15 to 30 candidates. Record the URL for each.

## Judge them

Open each page signed out. For each one, record:

- What the first screen says, in one line.
- Measurements: word count, number of tags or topics, number of links, image count, length of each field.
- What a reader can do next (install, read docs, contact).

Take measurements from the raw page or the raw API response, for example with a short script. A summary from a fetch tool is not a measurement. If a number is an estimate, write "about" and say why.
- Anything wrong: stale facts, broken links, empty fields.

## Pick

Pick three to seven pages. For each, write two or three concrete reasons, each one something you can check on another page. Good reasons:

- "The first sentence says what it does and for whom, in 14 words."
- "18 topics: 6 category words, 7 problem words, 5 platform words."
- "Install command in a code block in the first screen."

Weak reasons, do not use: "clean", "professional", "well written".

## Record

Write the table into the skill's `references/exemplars.md`:

| Page | URL | Read on | Why it is good |
|---|---|---|---|

Add the date at the top. Pages change, so the skill must say when you read them.
