# Process notes

## Why classify before fixing

The count you start with is usually wrong. "Six people said the link is broken" can sit inside a larger set of written reviews and an even larger set of bare ratings. Report each layer:

| Layer | What it tells you |
|---|---|
| All ratings | how many people rated anything |
| Written reviews | how many gave a reason |
| Delivery complaints | how many reasons were a broken or missing file |
| Bare ratings | how many you cannot read; never assume they are fine |

## Searching for the canonical file

Files that move are usually renamed too. Search in this order:

1. The exact title on the product page.
2. Earlier titles (from old emails, old product copy, or the title map).
3. A distinctive phrase from the content.
4. The file type and the date range when the product launched.

## The three logged-out checks

1. **Opens:** no sign-in page, no "request access", no expired-link page.
2. **File type:** the format the product page names (PDF, sheet, doc, template, zip).
3. **Content:** the current version of what the product page promises. Compare the title, the table of contents, or the first page.

A fix that passes 1 but not 2 or 3 is still broken.
